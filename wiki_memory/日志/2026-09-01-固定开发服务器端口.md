# 固定开发服务器端口

## 目标与结果

- 目标：解决执行 `npm run dev` 后因端口自动递增或打开旧端口而误连其他工程的问题。
- 结果：Vite 开发和预览服务器固定使用 `127.0.0.1:5189`，端口冲突时直接失败。

## 原因定位

原脚本只设置了 `--host 0.0.0.0`，没有端口和 `strictPort` 配置。多个工程同时运行时，Vite 会寻找其他端口，而用户常用的 `localhost:5173` 可能仍指向另一个工程；这属于启动配置问题，不是 p5 工程切换协议共享状态导致的串台。

## 文件变更

- 新增 `vite.config.js`，集中设置 `server` 和 `preview` 的 host、port、strictPort。
- 简化 `package.json` 的 `dev` 和 `preview` 脚本，避免重复覆盖配置。
- 更新 `README.md` 与当前状态页，记录固定访问地址和端口冲突行为。
- 保留用户整理到 `source/` 的教程参考与未来素材，并让 `runStart.cmd` 使用新的固定端口。
- 新增 [[决策/ADR-003-fixed-dev-port|ADR-003：固定开发服务器端口]]。

## 测试与验证

- 从仓库根目录启动 `npm run dev`，应输出 `http://127.0.0.1:5189/`。
- 访问 `/?project=flying-dandelion`，应加载飞鸟蒲公英宿主，而不是其他工程。
- `npm run build`、记忆 lint 和 `git diff --check` 在提交前执行。

## 下一步

如果未来需要局域网访问，应另行评估 host 暴露范围，不直接恢复 `0.0.0.0`。多工程仍使用同一个固定宿主和 URL 查询参数切换。
